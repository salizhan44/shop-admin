# shop-admin

Сайт для сотрудников магазина (Next.js + PostgreSQL). Клиенты сюда не заходят — только приложение через API.

Репозиторий приложения: [shop-mobile](https://github.com/salizhan44/shop-mobile) (ветка `dev`).

## Требования

- Node.js 20+
- Docker Desktop (PostgreSQL в контейнере)

## Первый запуск

```bash
npm install
cp .env.example .env
docker compose up -d
npx prisma migrate deploy
npm run db:seed
npm run dev
```

Сайт: http://localhost:3000

Проверка API: http://localhost:3000/api/health

## Файл `.env`

Скопируйте `.env.example` → `.env`. Файл `.env` **не коммитится** в Git — у каждого разработчика свой локальный.

| Переменная | Назначение | Пример |
|------------|------------|--------|
| `DATABASE_URL` | Подключение к Postgres | `postgresql://shop:shop@localhost:5432/shop` |
| `JWT_SECRET` | Секрет для токенов (локально любая строка) | `local-dev-change-me` |
| `STAFF_SEED_EMAIL` | Email владельца при seed | `owner@local.test` |
| `STAFF_SEED_PASSWORD` | Пароль владельца при seed | `changeme` |

## Вход на сайт (сотрудники)

После `npm run db:seed` создаётся **один** аккаунт владельца:

| Поле | Значение |
|------|----------|
| Email | `owner@local.test` |
| Пароль | `changeme` |

Других готовых логинов нет. Кладовщика, бухгалтера и поддержку добавляет владелец: **Панель → Сотрудники** (email + пароль от 8 символов + роль). У поля пароля есть **Показать / Скрыть**.

### Роли на сайте

| Роль | Что видит |
|------|-----------|
| **Владелец** (`OWNER`) | Ассортимент, остатки, заказы, сотрудники, поддержка, аналитика, учёт |
| **Склад** (`WAREHOUSE`) | Заказы (подтверждение / отклонение), остатки (только просмотр) |
| **Поддержка** (`SUPPORT`) | Обращения клиентов |
| **Бухгалтер** (`ACCOUNTANT`) | Учёт (список заказов и выручка) |

Клиент приложения (`customer`) **не может** войти на сайт — это отдельная таблица в базе.

## Склад и остатки

- Владелец задаёт остаток при создании товара и меняет его в **Ассортименте**.
- Кладовщик видит **Остатки** (только просмотр).
- При **подтверждении** заказа остаток уменьшается; если товара не хватает — подтверждение блокируется.

## Заказы и доставка

Клиент при оформлении указывает **телефон**, **адрес** и необязательный **комментарий**. Эти поля сохраняются в заказе и видны складу на странице **Заказы**.

Новый заказ из приложения создаётся со статусом `pending`. Подтверждение и отклонение — только у роли склада/владельца.

## Аналитика и учёт

- **Аналитика** (`/dashboard/analytics`) — только владелец: сводка продаж, топ товаров, продажи по дням.
- **Учёт** (`/dashboard/accounting`) — владелец и бухгалтер: список заказов, подтверждённая выручка.

Выручка считается только по заказам со статусом **подтверждён**. Суммы — в **сомах**.

## Ассортимент и валюта

- Цены вводятся и отображаются в **сомах** (например `89.00 сом`).
- `npm run db:seed` создаёт тестовый каталог **Товар1 один … Товар5 четыре** (категории — слова *один*, *два*, *три*, *четыре* в названии). Старые товары деактивируются. Повторный seed обновляет цены, остатки и описания.

## Обновления на экранах

На страницах **Заказы** и **Поддержка** — кнопка **Обновить**. Если с приложения пришло что-то новое, рядом загорается **зелёная точка** (проверка раз в ~30 сек). После нажатия «Обновить» точка гаснет.

## Клиенты (приложение)

Готового аккаунта клиента **нет**. В мобильном приложении нужна **регистрация**:

| Поле | Что вводить |
|------|-------------|
| Имя | любое, например `Тест` |
| Email | любой, например `client@local.test` |
| Пароль | **не короче 8 символов**, например `testpass8` |

На странице входа у пароля есть **Показать / Скрыть**.

- Email `owner@local.test` в приложении **не подойдёт** — это логин сотрудника на сайте.
- Один email нельзя зарегистрировать дважды.
