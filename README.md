# shop-admin

Сайт для сотрудников магазина (Next.js + PostgreSQL). Клиенты сюда не заходят — только приложение через API.

Репозиторий приложения: [shop-mobile](https://github.com/salizhan44/shop-mobile) (ветка `dev`). Как собрать Android и проверить пуши с телефона — там же, раздел **Как проверить**.

## Требования

- Node.js 20+
- Docker Desktop (PostgreSQL в контейнере)

## Первый запуск

```bash
npm install
cp .env.example .env
docker compose up -d
npx prisma migrate deploy
npm run db:seed
npm run dev
```

Сайт: http://localhost:3000

Проверка API: http://localhost:3000/api/health

После правки `.env` **перезапустите** `npm run dev` — иначе новые переменные (в том числе Firebase) не подхватятся.

## Файл `.env`

Скопируйте `.env.example` → `.env`. Файл `.env` **не коммитится** в Git — у каждого разработчика свой локальный.

| Переменная | Назначение | Пример |
|------------|------------|--------|
| `DATABASE_URL` | Подключение к Postgres | `postgresql://shop:shop@localhost:5432/shop` |
| `JWT_SECRET` | Секрет для токенов (локально любая строка) | `local-dev-change-me` |
| `STAFF_SEED_EMAIL` | Email владельца при seed | `owner@local.test` |
| `STAFF_SEED_PASSWORD` | Пароль владельца при seed | `changeme` |
| `GOOGLE_CLIENT_IDS` | Web Client ID Google (через запятую) | пусто, если вход через Google не нужен |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | JSON сервисного аккаунта Firebase (FCM) | см. раздел **Push-уведомления** |

## Вход на сайт (сотрудники)

После `npm run db:seed` создаётся **один** аккаунт владельца:

| Поле | Значение |
|------|----------|
| Email | `owner@local.test` |
| Пароль | `changeme` |

Других готовых логинов нет. Кладовщика, бухгалтера и поддержку добавляет владелец: **Панель → Сотрудники** (email + пароль от 8 символов + роль). У поля пароля есть **Показать / Скрыть**.

### Роли на сайте

| Роль | Что видит |
|------|-----------|
| **Владелец** (`OWNER`) | Ассортимент, промокоды, остатки, заказы, сотрудники, поддержка, аналитика, учёт |
| **Склад** (`WAREHOUSE`) | Заказы (подтверждение / отклонение), остатки (только просмотр) |
| **Поддержка** (`SUPPORT`) | Обращения клиентов |
| **Бухгалтер** (`ACCOUNTANT`) | Учёт (список заказов и выручка) |

Клиент приложения (`customer`) **не может** войти на сайт — это отдельная таблица в базе. Кладовщик не видит аналитику, учёт и промокоды — ни в меню, ни через API.

## Интерфейс панели

После входа — боковое меню (на телефоне открывается кнопкой ≡). Пункты меню зависят от роли. На **Обзоре** — краткие карточки (ожидающие заказы, открытые обращения, низкие остатки, выручка).

## Склад и остатки

- Владелец задаёт остаток при создании товара и меняет его в **Ассортименте**.
- Кладовщик видит **Остатки** (только просмотр).
- При **подтверждении** заказа остаток уменьшается; если товара не хватает — подтверждение блокируется.

## Заказы и доставка

Клиент при оформлении указывает **телефон**, **адрес** и необязательный **комментарий**. Эти поля сохраняются в заказе и видны складу на странице **Заказы**.

Новый заказ из приложения создаётся со статусом `pending`. Подтверждение и отклонение — только у роли склада/владельца. Отклонение **не удаляет** заказ: статус `rejected` и причина.

Полное стирание данных клиента — только из приложения, см. раздел **Удаление аккаунта клиентом**.

## Промокоды

Страница **Промокоды** (`/dashboard/promo`) — только владелец: создать код, выбрать эффект, лимит на всех и на одного клиента, включить/выключить.

После `npm run db:seed`:

| Код | Эффект | Лимит |
|-----|--------|--------|
| `ROLA10` | −10% | без общего лимита, **1 раз на клиента** |
| `FIRST100` | −200 сом | первые **100** применений, 1 раз на клиента |

Код вводится в приложении на экране оформления. Скидка считается при создании заказа. Вид «бесплатная доставка» пока даёт скидку 0 сом — отдельной платы за доставку в заказе нет.

## Push-уведомления (Android)

Пуш уходит клиенту при **оформлении**, **подтверждении** и **отклонении** заказа.

1. В [Firebase Console](https://console.firebase.google.com) проект с Android-приложением, package `com.rola.shop`.
2. **Project settings → Service accounts → Generate new private key** — JSON.
3. В `admin/.env` положите JSON **одной строкой** в `FIREBASE_SERVICE_ACCOUNT_JSON` (можно в кавычках). Не оставляйте мусор после JSON и не коммитьте ключ.
4. Перезапустите `npm run dev`.
5. На телефоне — development build с `google-services.json` (см. README приложения). Expo Go для этих пушей не подходит.

В логе админки при успешной отправке: `[push] FCM send ok`. Если токен с телефона есть, а ключа нет: `[push] FCM-токен есть, но FIREBASE_SERVICE_ACCOUNT_JSON не задан — пропуск`.

iOS-пуши отдельно (платный Apple Developer) в этой инструкции не разобраны.

## Как проверить

1. `npm run db:seed` и `npm run dev`. Войти владельцем (`owner@local.test` / `changeme`).
2. Собрать приложение по README `shop-mobile`, зарегистрировать клиента, разрешить уведомления. В логе админки должен быть `POST /api/customer/push-token` со статусом 200.
3. В приложении: каталог → корзина → оформление. По желанию код `ROLA10`. Заказ появляется на сайте со статусом ожидания; клиенту приходит «Заказ оформлен».
4. **Заказы** → подтвердить. Остаток уменьшается, клиенту — «Заказ подтверждён». Отклонение — с причиной, заказ остаётся со статусом отклонён, пуш «Заказ отклонён».
5. **Промокоды**: создать свой код, выключить `ROLA10`, проверить, что повторно тот же клиент не применяет код дважды (лимит 1 на человека).
6. В приложении **Удалить аккаунт** → в админке нет этого клиента, его заказов и обращений.

Автопроверка без UI: `npm run test:bug-catcher` (TypeScript + проверки домена).

## Аналитика и учёт

- **Аналитика** (`/dashboard/analytics`) — только владелец: сводка продаж, топ товаров, продажи по дням.
- **Учёт** (`/dashboard/accounting`) — владелец и бухгалтер: список заказов, подтверждённая выручка.

Выручка считается только по заказам со статусом **подтверждён**. Суммы — в **сомах**.

## Ассортимент и валюта

- Цены вводятся и отображаются в **сомах** (например `89.00 сом`).
- `npm run db:seed` создаёт тестовый каталог **Товар1 один … Товар5 четыре** (категории — слова *один*, *два*, *три*, *четыре* в названии). Старые товары деактивируются. Повторный seed обновляет цены, остатки, описания и промокоды выше.

## Обновления на экранах

На страницах **Заказы** и **Поддержка** — кнопка **Обновить**. Если с приложения пришло что-то новое, рядом загорается **зелёная точка** (проверка раз в ~30 сек). После нажатия «Обновить» точка гаснет.

## Клиенты (приложение)

Готового аккаунта клиента **нет**. В мобильном приложении нужна **регистрация**:

| Поле | Что вводить |
|------|-------------|
| Имя | любое, например `Тест` |
| Email | любой, например `client@local.test` |
| Пароль | **не короче 8 символов**, например `testpass8` |

На странице входа у пароля есть **Показать / Скрыть**.

- Email `owner@local.test` в приложении **не подойдёт** — это логин сотрудника на сайте.
- Один email нельзя зарегистрировать дважды.

## Удаление аккаунта клиентом

Клиент может **полностью стереть себя** только из приложения: кнопка **Удалить аккаунт** в профиле или в меню ≡. Сайт сотрудников такой кнопки не даёт — склад и владелец чужие аккаунты с панели не удаляют.

После подтверждения («Профиль, заказы и обращения удалятся. Восстановить нельзя.») приложение вызывает `DELETE /api/customer/me` с токеном **этого клиента**. Токен сотрудника сюда не подходит.

Из базы и с диска уходит всё, что относится к этому человеку в магазине:

- профиль: имя, email, пароль / Google, домашний адрес, аватар, баллы лояльности, время в приложении
- корзина, сессии (refresh-токены), push-токены
- все заказы и позиции, в любом статусе — вместе с телефоном, адресом и комментарием в заказе
- обращения в поддержку и приложенные фото
- факты применения промокодов этим клиентом; счётчик использований кода уменьшается, чтобы слот не «висел»

После этого на сайте этого человека **нет**: ни в **Заказах**, ни в **Клиентах**, ни в **Поддержке**, ни в аналитике/учёте. Восстановить запись нельзя.

Что не откатывается:

- остаток на складе **не возвращается** (для уже подтверждённых заказов товар списан)
- каталог, сами промокоды, данные других клиентов и сотрудников не трогаются

Тот же email можно зарегистрировать заново — это **новый** аккаунт, старые заказы к нему не привяжутся.

```bash
npm run dev              # dev-сервер
npm run test:bug-catcher # TypeScript + проверки промо

```
